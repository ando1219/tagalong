# 凑伴 · Tagalong

**周末去哪儿，先找人一起去。**

「凑伴」是「周末城市探索指南」产品设计中的组队社交模块（方向二 ·「约伴出发」）：把发起、匹配、协同这三步做成一条流水线——从发一张拼场卡，到成团自动建群、行程置顶、结束一键分账，让"组队"从私聊里反复确认的麻烦事，变成几次点击就能完成的确定动作。

---

## 背景：组队难，到底难在哪三层

"凑不齐人"背后不是一个问题，而是三层摩擦叠加的结果：

| 层级 | 痛点 | 说明 |
|---|---|---|
| 信息层 | 有活动，没伙伴 | 各平台解决"哪里好玩"，却没人解决"和谁去"——这是被现有工具集体忽略的一环 |
| 决策层 | 一个人，想想就算了 | 独自决策的心理门槛远高于一群人已约好——组队场景用社交承诺替代个人意志力 |
| 执行层 | 拉了群，却死在筹备里 | 定时间、算账、通知变动的琐碎摩擦，经常让计划死在微信群里，而不是死在没人想去 |

## 设计思路

不做泛社交匹配，而是依附在具体活动场景上的轻社交——用户因为想去同一个地方而产生连接，天然过滤掉纯搭讪意图。整体拆成三段可产品化的路径：

```
发起 ──────▶ 匹配加入 ──────▶ 协同执行
把念头变成      用轻量信任信号      定时间、分钱、发通知
可被加入的入口   降低陌生人门槛      自动化，减少组织者负担
```

## 核心功能模块

### 1. 发起拼场（发起者视角）
- 从活动详情页一键发起，无需重填信息
- 设置招募条件：人数上限/下限、时间窗口、集合地点
- 预算预填：人均预估花费区间提前展示
- 审核方式可选：自动通过 / 发起人审核

### 2. 发现与加入（参与者视角）
- 拼场广场：按时间、距离、活动类型筛选
- 信任标签：同校认证、历史成团次数、过往评价
- 模板化申请：预设自我介绍模板，降低输入门槛
- 候补机制：满员自动转候补，有人退出自动递补

### 3. 成团协同（群组功能）
- 满足最低成团人数后自动建群，行程卡自动置顶
- AA 分账工具：一键发起，自动算人均，记录付款状态
- 变动自动通知：天气突变 / 人员退出实时推送全员

### 4. 信任与安全机制
- 同校 / 同城身份认证
- 一键举报与黑名单
- 活动期间位置一键分享给紧急联系人
- 活动后互评，沉淀信任分

### 5. 打卡与信任沉淀
- 成团完成后引导发布打卡，自动 @ 同行伙伴
- 历史拼场记录形成"探索足迹"
- 轻度游戏化：徽章与等级刺激持续产出内容

## 用户路径

**发起方：** 看到心仪活动 → 一键发起拼场 → 审核申请 → 满员自动建群 → 群内协同 → 结束发起 AA → 互评

**参与方：** 浏览拼场广场 → 提交申请 → 等待 / 候补递补 → 群内协同 → 参与活动 → 打卡 / 评价

设计底线：**发起成本要低于私聊拉群，加入成本要低于私下问朋友**。
